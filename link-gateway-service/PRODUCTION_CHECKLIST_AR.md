# قائمة التحويل إلى Link Production

الكود يرفض التشغيل في وضع الإنتاج إذا كان عنوان Link يحتوي على `test` أو
`sandbox`. لا تغيّر هذا الحارس ولا تستخدم بيانات الاختبار في الإنتاج.

## بيانات يجب استلامها رسميًا من Link

1. عنوان `LINK_GATEWAY_BASE_URL` للإنتاج.
2. تحديد العقد المستخدم: `LINK_API_PROFILE=tharwatt` أو `unified`.
3. مسار الاستعلام عن الحالة `LINK_STATUS_PATH` وعينة استجابة ناجحة وفاشلة.
4. `LINK_MERCHANT_ORG_CODE` و`LINK_MERCHANT_ACCOUNT_ID` ونوع الحساب.
5. بيانات OAuth إذا كان العقد `unified`.
6. رسوم التاجر المتعاقد عليها إذا كان العقد `tharwatt`.
7. نطاق/نطاقات صور المحافظ لإضافتها إلى `LINK_LOGO_HOSTS`.
8. محفظة اختبار إنتاج محدودة واختبار end-to-end مع ممثل Link.

## الإعداد

انسخ `.env.production.example` إلى `.env` وأدخل القيم الفعلية. ولخدمة
FastAPI اضبط:

```env
APP_ENV=production
LINK_GATEWAY_URL=http://link-gateway:3000
LINK_GATEWAY_API_KEY=<نفس API_KEY في خدمة Link Gateway>
```

يجب أن يكون `API_KEY` عشوائيًا ومستقلًا بطول 32 محرفًا على الأقل، وألا يظهر
في الواجهة الأمامية أو سجلات التشغيل.

## اختبار القبول قبل فتح الدفع للعملاء

1. `npm ci && npm test` ينجحان.
2. `docker compose config --quiet` ينجح.
3. `/health` يعيد 200.
4. جلب المحافظ يعيد بيانات Link الحقيقية، ولا يعيد قائمة ثابتة عند قطع الشبكة.
5. بدء الدفع يرسل OTP حقيقيًا ويعيد resource token صادرًا من Link.
6. OTP خاطئ لا يغيّر الاشتراك ولا يسجل `SUCCESS`.
7. OTP صحيح ينتج transaction id حقيقيًا ثم يفعّل الاشتراك مرة واحدة فقط.
8. قطع الاتصال بعد إرسال OTP يترك العملية `PENDING`، ثم يحسمها status endpoint.
9. مطابقة transaction id والمبلغ مع كشف Link والتسوية المالية.
10. تدوير مفاتيح الاختبار وحذفها قبل النشر.

لا يتم إعلان الجاهزية المالية قبل نجاح البنود 5–9 بحضور بيانات اعتماد ومحفظة
إنتاج صادرتين من Link.
