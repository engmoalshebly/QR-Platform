# Qentry Field — تطبيق البوابات

تطبيق ميداني منفصل لمسّاحي بوابات الحفلات. لا يقدّم لوحة المؤسسة أو الفريق، ولا يفتح الكاميرا إلا بعد التحقق من وردية فعّالة وبوابة محددة وجلسة جهاز صالحة.

## التشغيل الآن عبر Expo Go

1. ثبّت **Expo Go** من متجر الهاتف.
2. اجعل الهاتف والكمبيوتر على شبكة Wi‑Fi نفسها.
3. شغّل من هذا المجلد:

   ```powershell
   npm run start -- --lan
   ```

4. امسح QR الذي يظهر في الطرفية بواسطة Expo Go.

يستخدم التطوير المحلي API التالي عبر الشبكة: `http://192.168.0.134:8021/api/v1`، وقد تم التحقق أن صحته متاحة من هذا العنوان.
لا تستخدم `localhost` في الهاتف؛ فهو يشير إلى الهاتف نفسه. إذا تغيّر عنوان الشبكة، حدّث `EXPO_PUBLIC_API_URL` في `.env` ثم أعد تشغيل Metro.

## ما الذي يعمل في Expo Go

- تسجيل الدخول بالحساب الشخصي واختيار مساحة العمل.
- عرض ورديات العضو فقط وبدء جلسة جهاز واحدة مع البوابة.
- مسح QR وCode128 بالكاميرا.
- التحقق الذري في الخادم، ودعم أعداد الدخول للدعوات الجماعية.
- إدخال رمز يدوي والبحث المحدود ضمن الحفل.
- نتيجة قبول/رفض/تحتاج مشرف، وطلب مساعدة وإنهاء جلسة الجهاز.
- حفظ رمز الدخول وجلسة الجهاز في `expo-secure-store` فقط.

لا يحتفظ Expo Go محلياً بحزمة دعوات أو طابور مسحات؛ لذلك يمنع المسح عند انقطاع الشبكة بدلاً من حفظ بيانات الدعوات على نحو غير مشفر.

## APK داخلي قابل للتثبيت

ملف `eas.json` مجهز لبناء APK داخلي. بعد تسجيل الدخول إلى حساب Expo الذي يملكه المشروع:

```powershell
npx eas-cli@latest login
npx eas-cli@latest build --platform android --profile preview
```

سيُنتج `preview` ملف APK قابل للتثبيت المباشر. إصدار Google Play يستخدم `production` وينتج AAB موقّعاً.

## الخطوة التالية للإصدار الإنتاجي دون اتصال

وضع البوابات دون اتصال يحتاج قاعدة بيانات مشفرة ومفتاحاً محفوظاً في KeyStore/Keychain، ولذلك يُنفّذ في Development Build/APK وليس Expo Go. الخلفية وPWA تملكان بالفعل حزمة العمل والمزامنة الآمنة؛ تُنقل هذه الطبقة للتطبيق الأصلي بعد اعتماد مكتبة SQLite مشفرة في Development Build.
