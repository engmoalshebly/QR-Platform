# خطة الإصلاح والتجهيز للإنتاج — منظومة إنشاء الدعوات

التاريخ: 18 أكتوبر 2026.

هذه الخطة تغلق الفجوات الفعلية بين ما بُني (P0–P3 محلياً، وP4 جزئياً) وبين «جاهز للإنتاج». مصدرها [تحليل الكود](INVITATION_GENERATION_PRODUCTION_PLAN_AR.md) وقراءة المكوّنات، وليست افتراضات. تكمل [الخطة الأصلية](INVITATION_GENERATION_PRODUCTION_PLAN_AR.md) ولا تلغيها: P5 وP6 فيها تبقيان المرجع للقياس والنشر، وهذه الخطة تضيف ما يسبقهما ويحدد بوابات الدخول.

## 1) الوضع الراهن بالأدلة

| البند | الحالة |
|---|---|
| P0 | منشورة |
| P1–P3 | مكتملة محلياً؛ أعلام `GENERATION_OPERATIONS_ENABLED` و`GENERATION_WORKER_ENABLED` مغلقة |
| P4 | قيد التنفيذ (المتابعة، السجل، ترحيل المستهلكين، الاستيراد الخادمي في الواجهة) |
| اختبارات | خادم 241 ناجح؛ الواجهة: tsc/eslint/build فقط، Playwright لم يُشغَّل محلياً |
| **التحكم بالإصدار** | **كل ملفات التوليد (`generation_*`، الترحيلات v79–v83، الاختبارات، الوثائق) غير مُلتزمة (untracked)، فلا يمرّ أي منها بـCI** |
| المراقبة | [metrics.py](../app/metrics.py) يحتوي عدّادات الطلبات فقط؛ لا مؤشرات للتوليد |
| التشغيل | [RUNBOOK.md](../deploy/RUNBOOK.md) بلا قسم للتوليد |
| السعة | قياس محلي فقط (10,000 سجل: 492ث، ذروة 131MiB)؛ لا قياس على موارد الإنتاج |

تصحيح لتحليلي السابق: تنظيف مساحة العمل في الناشر يقرأ مجلدات المهام فقط (`iterdir`) وليس `os.walk` كاملاً، فتكلفته صغيرة؛ المطلوب هو فقط ضبط التواتر (بند R-04).

## 2) مبادئ التنفيذ

1. لا يُفعَّل علم قبل اجتياز **بوابته** (القسم 8). كل بند يُغلق بدليل قابل للفحص (اختبار أو قياس أو سجل)، لا بتصريح.
2. إضافات متوافقة فقط: لا حذف أعمدة أو حالات، ولا تغيير ردود 201 القديمة بصمت.
3. كل تغيير يمرّ بـCI قبل الاعتماد؛ لا يعتمد على اختبار محلي وحده.
4. عند الشك يُغلق العلم ولا يُحذف شيء. الرجوع = إيقاف القبول الجديد مع بقاء القراءة والتنزيل والعامل.

## 9) المسار G — النشر التدريجي (P6)

1. **قبل الإطلاق:** نسخة احتياطية متحققة، حفظ صور API/العامل/الواجهة السابقة، نشر الترحيلات v79–v83 وحدها (إضافية) مع الأعلام مغلقة، ومقارنة أعداد الدعوات والحصص والدفعات قبل/بعد.
2. **staging ← مؤسسة اختبار واحدة** بعمليات مصرح بها (لا إرسال رسائل للعملاء).
3. **توسع:** 10% ثم 50% ثم 100%، لا ينتقل لخطوة إلا بعد ثبات القياس 24 ساعة. **تنفيذ واحد للطلب** (لا محركان على الدعوات نفسها).
4. **ترتيب التفعيل:** صورة موحدة ← `GENERATION_WORKER_ENABLED` + ناشر (profile `generation`) ← واجهة P4 ← `GENERATION_OPERATIONS_ENABLED` (يرفض الإعداد تفعيله دون العامل). مسارات الإنشاء القديمة ترفض بـ`GENERATION_CONTRACT_UPGRADE`، لذا **تُنشر الواجهة قبل العلم**.
5. **الدفعة القديمة المعلقة في الإنتاج:** تُراجع يدوياً بإجراء مدقق، ولا تُعاد تلقائياً ولا تُنشأ دعوات مكررة.
6. **مفتاح الإيقاف:** إغلاق `GENERATION_OPERATIONS_ENABLED` يوقف القبول الجديد فقط؛ القراءة والتنزيل والعامل المتوافق يبقون لاستكمال المقبول. لا يُرجَع العامل لنسخة لا تفهم العمليات الجديدة، ولا تُحذف جداول.
7. **بعد الاستقرار:** إنهاء المرحلة الانتقالية وإغلاق المسار القديم بإعلان مسبق وفترة تحذير.

**البوابة G6 (اعتماد الإنتاج):** كل ما سبق + تمرين رجوع ناجح + سجل اعتماد موقّع.
