# نتيجة المرحلة الأولى — صحة إنشاء الدعوات

التاريخ: 13 أكتوبر 2026. نطاق العمل: P0 من [خطة الإنتاج](INVITATION_GENERATION_PRODUCTION_PLAN_AR.md#phase-p0).

هذه النتيجة تخص الإصلاح والتحقق المحليين. نُشرت إصلاحات P0 بعد التحقق المحلي ونسخ احتياطي؛ [دليل النشر وفحوص الجاهزية](INVITATION_GENERATION_P0_DEPLOYMENT.json). لم يُشغّل اختبار حمل إنتاجي أو تُنشأ دعوات اختبار حقيقية أو تُرسل رسائل WhatsApp ضمن التحقق.

## الإصلاحات

| المهمة | التغيير | دليل التحقق |
|---|---|---|
| P0-01 | عقد موحد على الخادم للاسم والفئة والأشخاص والاتصال؛ رفض الأعداد الكسرية والقيم المخالفة، وتحقق التخطيط قبل الرسم | اختبارات الإدخال والتخطيط في `tests/test_invitation_generation_p0.py` |
| P0-02 | ترقية الاتصال من الحقول المخصصة إلى `guest_phone` و`guest_email` و`guest_whatsapp`؛ الهاتف الدولي مستقل عن الحقول المطبوعة | إدخال فعلي في PostgreSQL باستخدام «رقم الجوال» و`guest.phone`؛ اختبار متصفح لقالب يطبع الاسم فقط |
| P0-03 | عدد البطاقات يختلف عن عدد الأشخاص؛ إرجاع `vip_quota_used` و`normal_quota_used` باستثناء revoked وexpired؛ عرض غير محدود للحصة صفر | اختبار الإحصاءات: دعوة لثلاثة أشخاص مع دعوة ملغاة لسبعة يعيد استهلاكًا قدره 3؛ اختبارات حصص المجموعات والتزامن |
| P0-04 | مطابقة عدد الدعوات والرموز، ورفض نقص الملفات المطلوبة؛ إعادة قراءة نتائج العناصر قبل اعتماد حالة الدفعة؛ رسالة فشل واضحة | اختبارات سقوط باركود، ونقص ZIP، وفشل PDF والباركود في العامل |
| P0-05 | تضمين Amiri في صورة الخادم، وتشكيل العربية وترتيب النص المختلط وقياس عرض الاسم | اختبارات PDF للعربية والإنجليزية والنص المختلط وVIP؛ عينة مرئية؛ اختبار داخل الحاوية بالمستخدم غير الجذر |
| P0-06 | فحص `invitations.export` و`pdf_export` عند طلب الملفات وتشغيل العامل وإعادة التشغيل؛ إخفاء روابط الملفات من عرض الدعوات والدفعات والسجل دون التصريح | اختبارات حراسة التصدير وتنقيح الاستجابات؛ إنشاء دون ملفات ممكن باستخدام `output_formats: []` |
| P0-07 | تجديد تنزيل PDF/ZIP بعد مطابقة مرجع محفوظ للمؤسسة؛ توقيع لمدة 300 ثانية؛ عدم إرسال بيانات المنصة إلى التخزين؛ توضيح حد 1000 وحراسة المسارات | اختبارات ملكية المرجع والمسار، واختبار التنزيل المباشر على الحاسوب والهاتف |
| P0-08 | إضافة اختبارات رجوع دائمة بدل الاكتفاء بإعادة إنتاج العيوب | الملفات المذكورة أدناه و[أدلة التحقق](INVITATION_GENERATION_P0_RESULTS.json) |

## نتائج التحقق

- **96 اختبار خادم ناجحًا**، تشمل اختبارات PostgreSQL المعزولة والحصص والتزامن وجدول الدعوات. لا اختبارات متجاوزة في هذه المجموعة.
- **12 اختبار متصفح ناجحًا** على الحاسوب والهاتف، تشمل الاستيراد والاتصال وRSVP والتنزيل المجدد.
- نجاح `npm run build` للواجهة.
- بناء صورة الخادم `qentry-api:invitation-p0`، والتحقق من تضمين خط العربية أثناء توليد PDF داخل حاوية تعمل بالمستخدم غير الجذر ودون اتصال شبكي.
- مراجعة [عينة الطباعة](review-assets/invitation-generation-p0-arabic-label.png) بصريًا. المربعات الرمادية مواضع اختبار، وليست دعوات أو رموز دخول صالحة.

اختبارات الرجوع الجديدة: `tests/test_invitation_generation_p0.py`، و`tests/test_invitation_generation_p0_integration.py`، و`frontend/e2e/invitation-generation-p0.spec.ts`. عدّل اختباران سابقان بياناتهما لتوفير اسم ضيف صالح، مع إبقاء assertions الخاصة بعدم اعتماد المعاملة الفاشلة.

## الحدود المتبقية

الحد الحالي **1000 دعوة للعملية**، وليس إثباتًا لسعة آلاف العمليات المتزامنة. لا يزال المسار السريع ينفذ أعمال الرسم والتجميع في دورة الطلب، ولا تزال الملفات الكبيرة تحتاج إدارة موارد أفضل. تخزين بعض الملفات قبل فشل المعاملة قد يترك ملفات يتيمة تحتاج سياسة تنظيف. هذه أعمال المراحل التالية.

المرحلة التالية P1: سجل عملية دائم، ومفتاح لمنع التكرار، ولقطة بيانات ثابتة، وتسليم موثوق للطابور. تليها P2 لاستعادة العامل والإلغاء، ثم P3 لتقسيم الملفات والاستيراد الكبير. تبقى الدفعة القديمة العالقة المذكورة في تقرير المراجعة دون إعادة تشغيل تلقائية؛ مراجعتها الآمنة ضمن مرحلة الاستعادة.
