# لوحة OpenWA المنشورة

تاريخ النشر: 20 أكتوبر 2026.

الرابط المتاح: **https://notify.prideidea.com/dashboard**.

واجهة OpenWA الأصلية منشورة في حاوية مستقلة لا تفتح منافذ عامة مباشرة، خلف Caddy وباتصال HTTPS عبر Cloudflare. واجهات خدمة الإشعارات تبقى تحت `/v1` وتوثيقها تحت `/docs`؛ واجهات OpenWA تحت `/api` واتصالها المباشر تحت `/socket.io`.

## تسجيل الدخول

1. افتح الرابط أعلاه.
2. افتح ملف `/home/alrazi/.qentry/openwa-dashboard-admin.json` على الخادم أو في IDE.
3. انسخ قيمة `api_key` فقط إلى حقل **API Key** واضغط **Connect**.

المفتاح مخصص لإدارة OpenWA، وهو مختلف عن مفتاح `NOTIFY_ADMIN_KEY` ومفاتيح الأنظمة التي ترسل إشعارات. يخزن ملفه بصلاحية `600` خارج Git؛ لا تضعه في رابط أو كود واجهة أو توثيق. يظهر مفتاح الدخول في حقل مخفي ويحفظ في `sessionStorage` للتبويب الحالي. إغلاق التبويب ينهي التخزين؛ يمكن إلغاء المفتاح من صفحة API Keys عند الحاجة. الدور الإداري يمنح إدارة الجلسات والمفاتيح، فخصص مفاتيح أقل صلاحية للمشغلين عند الحاجة.

## إضافة رقم WhatsApp مرسل

1. افتح **Sessions**.
2. اضغط **New Session**.
3. أدخل اسماً مميزاً بحروف إنجليزية صغيرة وأرقام وشرطات، مثل `support-number`، ثم **Create**.
4. في بطاقة الجلسة الجديدة اضغط **Start**، ثم اعرض QR إن لم يفتح تلقائياً.
5. من الهاتف الخاص بالرقم الجديد: WhatsApp ← الأجهزة المرتبطة ← ربط جهاز، ثم امسح QR.
6. انتظر الحالة **Connected** وتحقق من الرقم المعروض.

كل رقم مرسل يحتاج جلسة مستقلة. رقم المستلم لا يحتاج جلسة؛ يمرر في حقل `to` عند إرسال الإشعار. لا توقف أو تحذف جلسة رقم المنصة القائم عند إضافة رقم جديد.

**إضافة رقم في OpenWA لا تحول خدمة الإشعارات إليه تلقائياً.** الخدمة المستقلة الحالية ترسل من جلسة واحدة يحددها `OPENWA_SESSION_ID`. لاختيار الرقم الجديد كمرسل للخدمة يلزم إصدار operator key مقيد بالجلسة الجديدة، وتحديث مفتاح المزود ومعرف الجلسة في ملف بيئة الخدمة، وإعادة إنشاء حاويتها وتسجيل Webhook جديد. واجهة اختيار مرسل لكل نظام أو لكل طلب ليست منفذة حالياً.

عند تغيير المرسل راجع الطلبات المعلقة أولاً، ولا تنقلها إلى رقم مختلف دون قصد. احتفظ بجلسة منصة الدعوات مستقلة عن التجربة.

## ما أُصلح

- إضافة بناء إنتاج للوحة React باستخدام Node 22، وخادم Nginx لا يعمل كـroot، بنظام ملفات للقراءة فقط وشبكة Docker الخاصة.
- فصل توجيه ملفات الواجهة عن API وSocket.IO، وإتاحة اللوحة على نطاق `notify` المنشور بالفعل.
- السماح بأصول اللوحة المحددة في CORS لدى مزود OpenWA.
- دعم مصادقة Socket.IO من `handshake.auth`؛ الواجهة لا تضع المفتاح في query string.
- تصحيح الاشتراك في جلسات المستخدم والتعامل مع رسائل الأحداث المغلفة وفق بروتوكول الخادم؛ كانت الواجهة تستمع لأسماء أحداث مختلفة ولا تشترك في الغرف.
- تصحيح قبول تسجيل الدخول ليتطلب `valid=true`، ومسح ذاكرة الاستعلامات عند تبديل الحساب أو تسجيل الخروج، وحذف الاعتماد على دور مخزن في localStorage عند إعادة التحقق.

## النطاق المخصص الاختياري

Caddy مهيأ أيضاً لـ`https://openwa.prideidea.com/` و`https://wa.prideidea.com/`، لكنهما لم يكونا قابلين للحل عبر DNS وقت النشر. الرابط العامل لا يحتاجهما. لتفعيل نطاق OpenWA المنفصل، أضف سجل A: الاسم `openwa`، العنوان `217.216.79.195`، وProxy مفعّل في Cloudflare، مع Full (strict). شهادة Origin الموجودة تغطي النطاق. بعد انتشار DNS يصبح الرابط المباشر متاحاً دون تغيير الحاويات.

## إعادة النشر

```bash
# بناء التعديل المحدود لمصادقة WebSocket فوق الإصدار الموجود
 docker build -f OpenWA/Dockerfile.dashboard-auth \
  -t openwa-api:dashboard-20261020 OpenWA
# تطبيق إعداد API بما فيه أصول CORS المعتمدة
QENTRY_ETC_DIR="$HOME/.qentry" scripts/ops/openwa-compose.sh up -d --no-deps openwa-api
# بناء ونشر الواجهة
 docker compose -f OpenWA/docker-compose.dashboard.yml up -d --build
# التحقق وإعادة تحميل الوكيل
 docker exec qentry-prod-caddy-1 caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
 docker exec qentry-prod-caddy-1 caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

صورة API مبنية كتعديل محدود فوق `openwa-api:whatsapp-20261013` الموجودة، وتتحقق أداة البناء من مطابقة موضع التعديل قبل تطبيقه. التعديل نفسه موجود في المصدر `OpenWA/src/modules/events/events.gateway.ts` ليبقى عند بناء الإصدار الكامل لاحقاً. عند الانتقال إلى إصدار مزود جديد، راجع الصورة الأساسية ولا تعاود استخدام overlay بصورة عمياء.

## التحقق

الاختبار التشغيلي في `scripts/ops/check_openwa_dashboard.cjs` يستخدم Playwright ومفتاح الملف المحمي؛ ينشئ جلسة مؤقتة تخصه ويبدأها للحصول على QR ثم يحذفها. لا يربط هاتفاً ولا يرسل رسائل. لا يطبع المفتاح ولا يسجل traces تحتويه. يفحص الدخول ورفض المفتاح الخاطئ وإنشاء الجلسات وQR واشتراك WebSocket وعدم وجود المفتاح في URL وعرض الجوال.

```bash
docker run --rm --network qentry-prod_app \
  --add-host notify.prideidea.com:172.28.20.2 --ipc=host \
  -v "$PWD:/workspace:ro" \
  -v "$HOME/.qentry/openwa-dashboard-admin.json:/run/credentials.json:ro" \
  -e OPENWA_DASHBOARD_CREDENTIALS=/run/credentials.json \
  -e OPENWA_TEST_ORIGIN_DIRECT=1 -w /workspace \
  mcr.microsoft.com/playwright:v1.62.1-noble \
  node scripts/ops/check_openwa_dashboard.cjs
```

اختبار المتصفح داخل الحاوية يصل مباشرة إلى Caddy ويقبل شهادة Origin ضمن الاختبار فقط. فحص HTTPS العام يتم مستقلاً عبر Cloudflare دون تعطيل التحقق من الشهادة. لا يعطل التطبيق أو الوكيل التحقق من الشهادات في تشغيله العادي.

نتيجة التحقق: نجح السيناريو كاملاً في المتصفح دون أخطاء JavaScript أو تجاوز أفقي في عرض الجوال، وحُذفت الجلسة المؤقتة. HTTPS العام للوحة والشعار والأيقونة أعاد 200. بعد النشر بقي الرقم السابق بحالة `ready`، وحاويات لوحة OpenWA ومزودها وخدمة الإشعارات وعامل إرسال المنصة بحالة `healthy`. الأدلة المختصرة في `OPENWA_DASHBOARD_DEPLOYMENT.json`.

دليل الربط التفصيلي للمسارين، من الواجهة أو API، وإصدار مفتاح جلسة والإرسال وإيصالات التسليم: [ربط الأرقام والإرسال عبر API](WHATSAPP_NUMBER_ONBOARDING_API_AR.md).

## إصلاح صفحة Webhooks — 20 أكتوبر 2026

أعادت API في السجلات الحالية `events` كنص JSON مثل `"[\"message.ack\"]"`، بينما تتوقع الواجهة مصفوفة. أضيف تطبيع للاستجابات في طبقة API للعرض والقراءة والإنشاء والتعديل، مع قبول المصفوفة والنص JSON الصحيح، ورفض البيانات غير الصالحة كخطأ استعلام مرئي بدلاً من انهيار الصفحة. لم يتطلب الإصلاح تغيير اشتراكات Webhook القائمة أو أسرارها.

طوبقت قائمة الأحداث في نافذة الإضافة والتعديل مع أحداث المزود، ومنها `message.ack` و`session.status`. الاختبار المخصص في `scripts/ops/check_openwa_webhooks.cjs` يراجع البيانات الحية ثم يحاكي صيغتي الأحداث وبيانات غير صالحة في المتصفح، ويفتح نافذة التعديل دون حفظ أي تعديل أو إرسال طلب اختبار إلى callback.
