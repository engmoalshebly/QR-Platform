# نتيجة المرحلة الثانية — P1

التاريخ: 13 أكتوبر 2026، بتوقيت عدن.

**P0 نُشرت وتحققت جاهزيتها. P1 مكتملة بالتحقق المحلي، ولم يُنشر ترحيلها أو صورتها إلى الإنتاج.** يبقى القبول الجديد معطّلًا حتى اكتمال العامل الموثوق في P2؛ مسارات الإنشاء الحالية تعمل على نسخة P0 المنشورة.

## ما نُفّذ

| المهمة | النتيجة |
|---|---|
| P1-01 | جداول العمليات والاستيراد والصفوف وأصول اللقطات وربطها، وoutbox والملفات وتغطية الملفات للصفوف؛ ربط الدعوات والدفعات والعناصر بالعملية |
| P1-02 | تفرد الطلب داخل المؤسسة، وصف المصدر، وترتيب الدفعة؛ علاقات مركبة تمنع الربط بين مؤسسات أو عمليات مختلفة؛ RLS مفروضة مع فهارس للمتابعة والترقيم |
| P1-03 | [عقد API موثق للإصدار 1](INVITATION_GENERATION_OPERATIONS_API_AR.md)، وقبول 202 مع معرّف العملية؛ قراءة حالة محدودة دون بيانات ضيوف، وصفوف وملفات بصفحات وصلاحياتها |
| P1-04 | الدعوات بإدخال مجموعي؛ حفظ العملية والصفوف والحصة الشهرية وحصة التخزين والدفعات وoutbox والتدقيق في معاملة اعتماد واحدة، دون رسم أو رفع أو نشر مهمة داخلها |
| P1-05 | قفل ومعرّف طلب ثابت وبصمة مدخلات؛ تكرار الطلب يعيد العملية نفسها، والمفتاح نفسه لمدخلات مختلفة يعيد 409 |
| P1-06 | نسخة ثابتة للحدث والتخطيط والقالب والعناصر والخطوط والصور والخلفية؛ بصمات SHA-256 وأصول خاصة غير قابلة للتعديل، مع منع العامل القديم من استعمال القالب الحي لهذه العمليات |
| P1-07 | سقف العمليات والبطاقات النشطة والمؤسسة، مع Retry-After قبل الخصم؛ حد تشغيلي 1000 بطاقة، ودفعات 100 بطاقة؛ تجهيز اللقطات محدود بطلبين لكل عملية API |
| P1-08 | اختبارات HTTP وتزامن وRLS وصلاحيات وحصص وتراجع ولقطات، على PostgreSQL معزولة وباستخدام دور التطبيق الفعلي |

الترحيل الإضافي هو `supabase/migration_v79_generation_operations.sql`. جُرّب تسلسل الترحيلات كاملًا على قاعدة فارغة؛ انتهى إلى 88 جدولًا عامًا. يتطلب تطبيق P1 هذا الترحيل قبل التشغيل، حتى إذا كان قبول العمليات معطّلًا.

أضيفت المؤسسة إلى عناصر الدفعة مع تعبئتها من الدفعة الأم وترحيل متوافق مع الإدخال القديم. تُشتق المؤسسة في الإدخالات القديمة تلقائيًا، وتُلزم RLS وتحافظ على وصول الحدث المُدار المصرح به. إجراءات البدء والإلغاء والإعادة القديمة لا تغيّر أجزاء عملية P1.

## الأدلة

- **850 اختبارًا ناجحًا** في المجموعة الكاملة، وتغطية **49.52%** متجاوزة شرط CI البالغ 35%. توجد **29 حالة متجاوزة مقصودة** في سجل التفويض لمسارات عامة أو خاصة بالرمز؛ ليست اختبارات قاعدة بيانات تعذر تشغيلها.
- **18 اختبار عقد P1 ناجحًا** في الفحص المركّز الأخير.
- **100 طلب HTTP متزامنًا** بالبيانات والمفتاح نفسيهما أعادت جميعها 202 ومعرّف عملية واحد. المحصلة: عملية واحدة، استيراد واحد، ثلاث دعوات وثلاثة عناصر، دفعة وoutbox واحدان، واستهلاك ثلاثة أشخاص وحدث تدقيق واحد.
- طلبان بمفتاحين مختلفين على آخر مقعد: قبول واحد ورفض الآخر، ودعوة واستهلاك واحدان.
- فشل متعمّد في التدقيق بعد إنشاء السجلات يعيد العملية والصفوف والدعوات والدفعات وoutbox والحصة كلها.
- دور مخصص يحمل `invitations.create` فقط ينشئ دون ملفات، ويتابع حالته؛ لا يستطيع قراءة الصفوف أو طلب PDF دون صلاحياتهما.
- المفتاح نفسه في مؤسستين مستقل؛ ربط دفعة بعملية المؤسسة الأخرى مرفوض بقيود قاعدة البيانات. قراءة دور التطبيق دون فلتر صريح ما زالت لا ترى بيانات المؤسسة الأخرى.
- تعديل القالب وعناصره بعد القبول لا يغير اللقطة الأصلية. خلفية من رابط منتهٍ تحفظ من الكائن الخاص، والمرجع المتكرر يقرأ مرة واحدة ويخزّن ويحتسب مرة واحدة.
- القالب المفرط في الحجم يرفض قبل نسخ أصوله أو احتساب الاستخدام. حدود اللقطة 200 عنصر و6MiB لبيانات العناصر، و20MiB للأصل و40MiB للأصول الفريدة.
- بناء صورة `qentry-api:invitation-p1` وفحص استيراد API وعقد 202 وتعطيل القبول افتراضيًا داخل حاوية بالمستخدم غير الجذر ودون شبكة.
- فحص بدء التشغيل أثبت اكتمال مخطط قاعدة البيانات وعزل دور التطبيق الفعلي. تُخفى معاملات SQL في السجلات لحماية الاتصال والرموز والبيانات الثنائية.

[ملف الأدلة والبصمات](INVITATION_GENERATION_P1_RESULTS.json). اختبارات المرحلة الدائمة في `tests/test_generation_operations.py`؛ حدّث سجل اختبار التفويض ليوثق حماية تفعيل الحساب برمز الدعوة وwebhook بالتوقيع، واختبار جرد RLS ليتحقق من الدور والمحمولات الفعلية لسياسة FOR ALL الخاصة بالجداول الجديدة، بدل اشتراط أربع سياسات شكليًا.

## ما بقي للإنتاج

لم يُختبر حمل إنتاجي أو توليد ملفات من العملية الجديدة؛ لم تُرسل رسائل حقيقية. اختبار التزامن يعزل القبول والتخزين والحصص، مع تجاوز محدّد لمحدد معدل الدخول في هذا الاختبار فقط. لا يُستنتج منه إنجاز ملفات عشرة آلاف ضيف أو معالجة ألف مهمة CPU متزامنة.

**التالي P2:** ناشر outbox، والعامل الذي يقرأ اللقطات المثبتة، وملكية التنفيذ وheartbeat والاستعادة والإلغاء وإعادة الفاشل. تبقى `GENERATION_OPERATIONS_ENABLED=false` إلى أن يجتاز هذا المسار اختبار التشغيل. الاستيراد الثنائي الكبير وتقسيم الملفات في P3، وتوحيد واجهة المستخدم في P4.
